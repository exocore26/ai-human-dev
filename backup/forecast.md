# Forecast 2026–2030

Where I think this goes, written as *what will be proven by when*
rather than what is hoped. Each year adds a tier, and each tier is
demonstrable by the end of its year. If a year's claim isn't met, it
will be visible on this page, not quietly dropped.

---

## 2026 — Experimentation

**What happens:** A year of build-in-public experiments with free AI
tools on a 4 GB laptop, documented on YouTube. The experiments
culminate in the consolidation of what was learned into a single
governed architecture: the META-SYSTEM.

**What is proven by year end:** That AI-assisted software development
is viable on minimal hardware and zero budget — and that the failure
modes (drift, hallucination, truncation, misalignment) are consistent
enough to be designed against, not just worked around.

**Status:** In progress. On track.

---

## 2027 — The System

**What happens:** The META-SYSTEM ships as a working, lifecycle-driven
factory. A non-technical user can describe a software project, walk it
through the eight-phase lifecycle, and produce a working artifact with
AI assistance that never leaves the guardrails — contracts, checkpoints,
validation, repair, and human fallback all functioning.

**What is proven by year end:** That governance can be built into the
tool rather than bolted on, and that a non-technical user can complete a
real software project through it without managing the AI's failures.

**Dependency:** The three-tier architecture, the discussion-packet
governance model, and the archiver must all be working and stable.

---

## 2028 — Packaged Users

**What happens:** The End User tier is packaged into domain-specific
clones. A clone is a version of the end-user experience tuned for one
domain — a specific kind of software project, a specific industry, a
specific workflow — that can be handed to a user without them needing
the rest of the system.

**What is proven by year end:** That the architecture generalises beyond
software development. The same governed-lifecycle pattern works for any
domain where a task has phases, inputs, and a checkable output.

**Dependency:** The atom definition must be stable enough that a clone
is a *selection* of atoms, not a re-design.

---

## 2029 — The Engineer Tier for Project Managers

**What happens:** The Systems Engineer tier ships as a package that
project managers can use to manage their own users and projects. A PM
composes lifecycles from the Architect's palette, assigns users, and
monitors runs — without touching AI, because the AI never touches them.

**What is proven by year end:** That the tier structure maps onto real
organisational roles. The PM is a real job, the Engineer tier is the
tool for that job, and the isolation (no AI exposure) holds in practice.

**Dependency:** A stable palette of atoms, and a workstation that a
non-technical PM can use without training.

---

## 2030 — Personal Operating Systems

**What happens:** The meta engine matures enough that advanced users can
compose their own systems-of-systems: personal operating systems for
their own domains, with AI guidance, guardrails, contract creation, and
model configuration. The architecture becomes a platform rather than a
product.

**What is proven by year end:** That the governed-atom pattern is
general enough to be a platform for building systems, not just a tool
for building software.

**Dependency:** Every prior year's tier must be stable, and the atom
must be proven as a *composable* unit, not just a functional one.

---

## The shape of the arc

Each year adds one layer and packages it for one more kind of person:

| Year | Adds | Packages for |
|---|---|---|
| 2026 | The learning | (me) |
| 2027 | The system | the end user |
| 2028 | Domain clones | domain users |
| 2029 | Engineer tier | project managers |
| 2030 | Meta platform | advanced users |

The consistent rule across all five: **AI complexity moves upward, never
downward.** The End User never manages AI. The PM never manages AI. The
advanced user manages the *system* that manages the AI. If a future year
breaks that rule, the forecast is wrong, not just late.
